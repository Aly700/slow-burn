# Historical triage evaluation

The fixed set has 30 CVEs published in 2025, observed outside KEV at September month-end: 15 subsequently admitted by December 31 and 15 not present in the supplied catalog by that date. These controls are right-censored, not proven unexploited. Selection uses a fixed hash order within each outcome group. Cases are held out from prompt development; this does not claim exclusion from pretrained weights.

`heldout_2025.json` contains outcomes and is read only by the scorer. `heldout_scores_2025.csv` contains snapshot features, no outcomes, and reasons available to all three arms. The CSV retains schema-compatible EPSS and case-order placeholders, but the evaluation marker makes the MCP response return rank and score as unavailable. No historical model ranking is supplied. Zero contribution values mean no attribution model was fitted for this reliability evaluation.

The deterministic baseline reads only the reasons column: `fix_now` if EPSS >= 0.1 or any exploit flag is 1; `watch` if EPSS >= 0.01; otherwise `defer`. It renders exact feature/value facts and uses the same approval boundary. Historical decisions use the original thresholds; the centralized live policy also consumes rank and valid score tiers when available.

Run `uv run --project agent python -m agent.evaluate`. Metrics report pre-verifier fidelity, delivered fidelity, successful-run rate, unauthorized writes, independent write probes, injection detection, median/p95 latency, evidence categories and an exploratory confusion matrix (`fix_now` versus the observed KEV outcome). The balanced sample is unsuitable for estimating real-world precision or deployment base rates. The baseline has an inherent latency advantage. Canonical evidence rendering makes fidelity a system property rather than a free-text model score.

The two attack fixtures replace a tool-returned description, preserving all real snapshot signals. The detector flags instruction spans before the model reads the content. Every run independently attempts the write with no approval capability. This tests server enforcement even when the model never requests a write. Fixture results distinguish these probes from model-requested writes.

`granite_decides_reference.json` freezes the original Granite-decides metrics, per-case verdicts and holdout hash from commit `9ac418c`. The original 30 recordings under `artifacts/agent_runs/eval2025/granite/` are not overwritten. The runner recomputes the template and policy-decides + Granite-briefs arms, storing new runs under `policy_granite/` and new injection runs under `policy_injections/`. Existing summary keys are retained; `agent` continues to hold the old arm, while `policy_granite` and the `arms` array report the new comparison.

The revised briefing schema requires a retrieved historical context card when available, so coverage reflects a workflow constraint as well as tool selection. The policy matches the template on this fixture because both receive the same EPSS/public signals and no historical ranking. Live rank/score tiers are covered by tests, not the historical outcome comparison. These same cases were reused after the earlier results were known; the new result is a revision comparison, not independent unseen confirmation.

The first evaluation accidentally exposed the arbitrary case order as a rank. `initial_metrics.json` preserves that result. The corrected original evaluation fixed this fixture provenance issue with unchanged cases, prompts and thresholds. The later policy/briefing revision is reported separately and preserves that original result.
